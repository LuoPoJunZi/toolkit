# 运行级自检清单（当前主菜单）

本文用于在真实 VPS 环境中逐菜单验证功能可用性，避免“看起来有菜单、实际空执行”。

## 1. 自检前准备

- [ ] 使用 `root` 用户登录
- [ ] 更新到最新脚本：`bash <(curl -fsSL https://raw.githubusercontent.com/LuoPoJunZi/toolkit/main/install.sh)`
- [ ] 启动工具箱：`z`
- [ ] 记录日志路径：
  - 操作日志：`/opt/luopo-toolkit/logs/action.log`
  - 错误日志：`/opt/luopo-toolkit/logs/error.log`

## 2. 通用通过标准

- [ ] 每个功能必须有明确执行结果（成功或失败提示）
- [ ] 不允许只出现“按回车继续...”且没有过程输出
- [ ] 失败时需有可理解的错误提示（依赖缺失/下载失败/执行失败）
- [ ] 高风险操作需有确认提示（如重启、卸载、批量操作）
- [ ] 启动主菜单时不应加载未选择的业务模块，首次进入各功能后仍可正常执行
- [ ] 主菜单与基础工具、WARP、网络测试、后台工作菜单编号及文本对齐正常，输入结束后正常返回

## 3. 主菜单逐项检查

### 1. 系统概览

- [ ] 输出系统/资源/网络分区信息
- [ ] 无 `numfmt` 报错
- [ ] 核心字段不为空（主机名、内核、内存、磁盘、IPv4）

### 2. 系统更新

- [ ] 有更新过程输出
- [ ] 有明确完成状态（成功/失败）

### 3. 系统清理

- [ ] 有清理过程输出
- [ ] 有明确完成状态（成功/失败）

### 4. 基础工具

- [ ] 状态表格正常显示，已安装/未安装工具可区分
- [ ] 任意 2 个安装项可执行，例如 `curl`、`tmux`
- [ ] 自定义安装/卸载输入无效项时有提示

### 5. BBR管理

- [ ] Alpine 环境下 `1/2` 开关 BBRv3 可执行
- [ ] 非 Alpine 环境可正常进入外部 BBR 套件
- [ ] 返回上级时没有多余二次暂停

### 6. Docker

- [ ] 顶部状态统计正常显示（容器/镜像/网络/卷）
- [ ] `1` 安装/更新 Docker 可执行
- [ ] `2` 全局状态有版本/清单输出
- [ ] `3/4/5/6` 子菜单进入与返回正常
- [ ] 删除容器时在当前流程完整列出运行中和已停止容器，可按编号选择，`0` 可取消
- [ ] 删除容器、镜像、网络和卷时均有清晰的对象信息与二次确认
- [ ] 启停/重启/日志/Shell、镜像导出、网络连接/断开、卷详情/备份/还原无需预先记忆名称或 ID
- [ ] 清理悬空镜像或未使用卷前先显示待清理列表，并要求确认
- [ ] `7/8/9/11/12/19/20` 有明确结果或确认提示

### 7. WARP管理

- [ ] `1/2/3` 可查看 WARP 状态、出口 IP 和 IPv4/IPv6 连通性
- [ ] `11/12/13` 可进入官方管理脚本并执行安装、更新或卸载流程
- [ ] `21/22/23/24` 可执行启动、停止、重启和模式切换，未安装时有明确提示
- [ ] 官方管理脚本下载失败时有明确失败输出，不应静默返回

### 8. 网络测试（重点）

- [ ] `1~4` 解锁检测有输出或失败提示
- [ ] `11~18` 回程/测速脚本可执行
- [ ] `21/22/31/32/33` 至少抽测 3 项有有效输出
- [ ] `15` 指定 IP 输入后确实执行到目标脚本

### 9. 建站管理

- [ ] 至少抽测 `1/21/23/31/38` 各 1 项
- [ ] 创建站点或反代后，Nginx 重载成功才提示成功
- [ ] 备份/恢复/卸载类有明确确认提示

### 10. 应用市场

- [ ] 应用列表完整显示
- [ ] 应用状态标记正确，读取状态文件失败时仍能显示完整本地清单
- [ ] 从主菜单首次进入应用市场后，旧编号安装标记仍能正确识别；安装或卸载后重新绘制会刷新状态
- [ ] 仅浏览或返回应用市场时不应预加载全部应用实现，首次选择应用后功能可正常进入
- [ ] 至少抽测 2 个应用可真正拉起安装/管理流程
- [ ] 进入应用市场不依赖额外远程索引仓库，断网时仍可显示本地应用清单
- [ ] 容器应用更新先成功拉取新镜像，再重建容器；拉取失败时原容器保持运行
- [ ] 共用安装流程拒绝非法端口，冲突后可重新输入，`0` 可取消；提示文本不会混入 Docker 端口参数
- [ ] 共用流程在依赖安装、Docker 服务、镜像下载、安装/更新回调失败时停止后续操作，不误报完成或写入安装标记
- [ ] 端口保存失败时保留原配置并明确提示；损坏的端口配置可回退读取容器映射
- [ ] Compose 应用更新保留现有 `.env` / `docker-compose.env` 和应用数据
- [ ] n8n、gpt-load、思源笔记更新时复用现有域名或凭据
- [ ] `b/r` 备份与还原入口有明确过程输出
- [ ] 备份失败不会留下可选择的半成品，同一秒重复备份不会覆盖；还原先校验压缩包，失败时提示且不显示完成
- [ ] 共用应用子菜单及还原提示在输入结束时正常返回，不继续重绘或执行操作

### 11. 后台工作

- [ ] `1~10` 固定工作区能进入/创建
- [ ] `21` SSH 常驻模式可开关
- [ ] `22/23/24` 创建、注入、删除工作区可执行

### 12. 系统工具

- [ ] 至少抽测 `1/6/12/15/17/20/31/34/99/102`
- [ ] 高风险项必须有确认提示
- [ ] 返回主菜单时不应出现多余二次暂停

### 99. 更新脚本

- [ ] Git 安装路径更新成功
- [ ] 非 Git 安装路径可走远程更新，且非空执行

### 88. 卸载脚本

- [ ] 执行后 `z` 命令不可用
